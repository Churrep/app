# Ближайшие задачи по «Джему»

## 1. Разделить лайк записи и предложение поиграть

Сейчас нажатие «Хочу поиграть» создаёт лайк человеку. Нужно дать музыканту два независимых действия.

- В ленте можно поставить лайк конкретной записи и снять его. В таблице `likes` хранить пару «кто поставил лайк, какую запись лайкнул». Сделать ссылку на запись обязательной, убрать `to_user_id` и обеспечить уникальность пары. Автора записи можно получить из `videos.user_id`.
- Из профиля музыканта можно отправить «Хочу поиграть». Для предложений завести отдельную таблицу с отправителем и получателем. Пара направленная: Аня → Борис и Борис → Аня — две разные строки. Исключить дубли и отправку самому себе.
- Развести действия в API и интерфейсе. В разделе входящих предложений должно быть видно, кто хочет поиграть и кому можно ответить взаимностью. Пересмотреть фильтр ленты: сегодня лайк скрывает остальные записи автора.

**Проверка.** Аня может лайкнуть две разные записи Бориса, снять один лайк и независимо от этого отправить ему предложение. Входящее предложение появляется только после нажатия «Хочу поиграть».

## 2. Вычислять взаимность по двум предложениям

Убрать таблицу `matches`. Два музыканта хотят поиграть вместе, когда в таблице предложений есть обе строки: Аня → Борис и Борис → Аня. Список совпадений и состояние кнопки в профиле должны использовать это правило. Заменить использование `match_id` в ответах API и клиенте; для перехода в профиль достаточно ID второго музыканта.

**Переход со старой схемы.** Задачи 1 и 2 выпускать согласованно. Старые лайки выражают желание поиграть: перенести их как предложения. Для существующих совпадений проверить наличие обоих направлений до удаления `matches`. Правило отмены предложения после взаимности согласовать отдельно: сейчас сервер запрещает отменять лайк после совпадения.

**Проверка.** Одно предложение видно получателю. Два встречных предложения дают по одному совпадению у каждого, в том числе при одновременной отправке. Лайки записей на этот результат не влияют.

## 3. Проверить синхронизацию записи и метронома

Сейчас браузер даёт четыре щелчка перед началом минусовки. Калибровка измеряет задержку между воспроизведением щелчка и его появлением на аудиовходе. Одно значение сохраняется в браузере и применяется при следующих записях, даже если музыкант сменил вход или выход.

- Проверить на телефоне два сценария: наушники и микрофон телефона; бас через инструментальный вход аудиоинтерфейса. Зафиксировать используемый выход и вход для каждого замера.
- Проверить попадание отсчёта в первую долю и согласовать, нужен ли клик во время самой записи. Отдельно проверить старт с середины песни: выбранный фрагмент может начинаться между долями.
- По результатам определить способ компенсации для каждого подключения. Проверить знак и величину сдвига в предпрослушивании и в серверном миксе, в том числе после смены устройства.

**Результат.** Описать способ измерения, фактическое расхождение в миллисекундах и согласованный допустимый порог. Показать на проверочной записи, что предпрослушивание и отправленный группе микс укладываются в этот порог.

## 4. Поддержать отдельные инструментальные дорожки

Сейчас у объявления одна готовая минусовка. Дать группе возможность загрузить несколько партий одной песни, например барабаны, бас и гитару. Каждая дорожка должна иметь название или обозначение инструмента и привязку к объявлению.

- Определить, как дорожки окажутся на общей временной шкале. Простой вариант для первой версии — группа экспортирует их от одного начала песни, включая тишину до вступления инструмента.
- В карточке объявления и при подготовке к записи дать музыканту послушать отдельную партию или несколько партий вместе.
- Согласовать, какие дорожки звучат во время записи и какие входят в отправленный группе микс. Учесть существующие объявления с одной минусовкой.

**Проверка.** Группа загружает три дорожки. Музыкант слушает каждую отдельно, включает две вместе, выбирает фрагмент и записывает свою партию. Партии остаются синхронными, а группа слышит отклик с согласованным аккомпанементом.
